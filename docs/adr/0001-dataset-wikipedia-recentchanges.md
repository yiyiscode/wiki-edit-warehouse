# ADR 0001:資料集由 GH Archive 改為維基百科 recentchanges API

- 狀態:已採納
- 日期:2026-11-11(決定)、2026-11-12(成文)
- 決策者:使用者;AI 提供實測與替代方案

## 背景

2026-11-07 的設計選了 GH Archive(每小時事件檔)加 GitHub REST API(每日 repo 屬性快照,供 SCD2 使用)。2026-11-11 重審 spec 時,先發現雙來源設計的幾個缺口,接著實測發現來源本身已退化。

### 原設計的缺口

1. GitHub API 只回傳現在的狀態,每日快照無法回補;SCD2 的歷史只能從開工日累積。
2. `dim_repo` 只涵蓋追蹤名單內的 repo,但事件包含所有 repo,未追蹤者沒有維度可連。
3. 追蹤名單若每日重算,同一小時重跑會載入不同的列,冪等測試無法定義。
4. 數千個 repo 在數週內的屬性變更極少,SCD2 幾乎只能靠合成資料展示。

### 實測:GH Archive 已退化(2026-11-11)

| 檔案 | 事件數 | PushEvent | 壓縮大小 |
|---|---|---|---|
| 2026-10-20 12 時 | 58,084 | 45,180 | 12.8 MB |
| 2026-11-09 03 時 | 5,604 | 2,252 | 4.0 MB |
| 2026-11-09 12 時 | 2,958 | 0 | 2.8 MB |

- 2026-10-12 至 2026-11-11 每天抽 0、6、12、18 時看檔案大小:10/12–10/14 約 14–17 MB;10/15 起掉到約 4–8 MB;之後回升兩次;10/26 12 時起停在約 2–7 MB。
- 收集器 repo `igrigorik/gharchive.org` 最後一次 push 為 2025-05-25(`gh api` 查詢,2026-11-11)。

### 他人回報(本專案未重現)

- 收集器每輪只抓一頁 100 筆;回報者估計目前只收到實際事件的 2–3%([issue #326](https://github.com/igrigorik/gharchive.org/issues/326))。
- GitHub 於 2025-10 重啟事件 id 序列,現有兩條平行序列,id 會互撞(同上)。原設計以 `event_id` 為唯一鍵;本專案抽的 3 個檔內無重複,跨檔未驗。
- OpenDigger 提供格式相容的鏡像,但維護者表示頻寬限 5 Mbit/s 共用,使用者回報約 5 KB/s([issue #323](https://github.com/igrigorik/gharchive.org/issues/323))。

## 決定

改用維基百科中文版(zhwiki)的 MediaWiki recentchanges API 作為唯一資料來源。

## 理由

1. **SCD2 有真實且可回補的變更。** 頁面改名是帶時間的 `move` 事件,含舊標題、新標題、新命名空間,`pageid` 不變。實測 zhwiki 單一小時有 5 筆、enwiki 有 30 筆。
2. **單一來源。** 不需要第二個 API 做每日快照,也不需要追蹤名單;上述缺口 1–3 不再存在。
3. **維度變更與事實在同一條流裡交錯**,「維度先於事實」的處理順序成為真實問題。
4. **原設計的骨架保留**:每小時增量、30 天回補、欄位不固定的 JSON(`logparams` 隨日誌類型而異)、來源自帶的 `bot` 旗標。
5. **來源由 Wikimedia 基金會營運**;實測 zhwiki 單小時 2,802 筆,`rcid` 無重複。

資料量與限速的實測數字見 SPEC 第 5、6 節。

## 替代方案

| 方案 | 優點 | 未採用的原因 |
|---|---|---|
| 留 GH Archive,定位為不完整的抽樣事件流 | SPEC 改動最小;量斷崖可當 DQ 素材 | 事件量分析不可信;來源可能停擺;SCD2 仍幾乎沒有真實變更 |
| 證交所開放資料 | 題材與金融業職缺相關;每日行情可回補多年(2025-11-10 仍可查);上市公司基本資料 1,099 家可做 SCD2 | 只有每日頻率;JSON 扁平,JSONB 與 MongoDB 的比較變弱;SCD2 歷史無法回補;SPEC 要大改 |
| YouBike 即時站點 | 即時、JSON、1,824 站 | 沒有歷史可回補;沒有事件型事實 |
| 自有職缺資料(優先度報告第 6 節) | 資料是自己的、故事連貫 | 沒有每小時增量與回補;資料在本機,不符合「雲端可存取」 |

以上數字皆為 2026-11-11 實測。

## 代價與後果

- 題材與求職領域無直接關聯。
- 來源只保留 30 天(實測:2026-10-14 可查、2026-10-12 已空)。raw 層成為唯一副本,必須永不刪除並備份;回補要盡早開始。
- 需處理分頁與 429 限速。
- zhwiki 30 天約 124 萬列(估計),量小;M5 前評估加入 enwiki(約 1,060 萬列,估計)。
- 快照型事實表由「repo 的 star 數」改為「頁面每日結束時的位元組大小」,較不直觀。
- GH Archive 的教訓保留為一條 DQ 規則:單小時筆數過低即警告。
